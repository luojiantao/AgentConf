# AI 方案执行器

## 目标

按照一份 executor-ready 的方案 Markdown 文档执行实现、验证和交付。执行时必须尊重方案中的 `方案元信息`、`阶段角色与职责`、`需求范围`、`非目标`、`执行约束`、`修改范围`、`实现步骤`、`验收标准`、`代码静态校验`、`运行验证方式` 和 `最终交付要求`。

遵循 `Doc/AIPrompt/AI提示词六要素设计指南.md` 定义的边界：

```text
Role + TechStack + Domain + Requirement + Constraints + Acceptance
```

`Role` 只提供身份、职责、判断视角、工作方式和职责边界。执行方案时，不得把技术栈、业务知识、当前需求、执行约束或验收标准解释为角色职责。

本 skill 只负责执行已有方案，不负责重新写方案。发现方案缺失、冲突或无法执行时，先说明阻塞点；不要自行扩大范围补成另一个方案。

## 执行原则

- 先完整阅读方案，再读取相关代码。不要只看标题或局部步骤就开始改文件。
- 严格按方案范围执行，不做方案外重构、统一格式化、无关清理或风格迁移。
- 优先使用方案指定的文件和模块；如果实际代码结构不同，先补充实际文件清单并说明差异。
- 如果方案与现有代码冲突，先停止并说明冲突；只有在冲突可局部修正且不扩大范围时才继续。
- 如果方案中的验证命令不适合当前仓库，选择等价且更贴近实际项目的验证方式，并说明替代原因。
- 实现后必须执行代码静态校验。运行验证不能替代静态校验。
- 对无法运行或无法确认的内容，明确列入剩余风险，不要假装已验证。
- 将 `Doc/AIPrompt/AIActor/README.md` 作为可用角色索引的唯一事实来源。方案中的角色必须使用 `角色文档` 列的精确 Role 索引。
- 执行前完整阅读每个已选 Role 索引对应的角色文档，确认角色职责和边界适合目标阶段。
- 每个阶段开始时只采用该阶段 Role 索引。角色是局部执行视角，不得覆盖方案范围、非目标、执行约束、安全规则或用户指令。
- 不要把前一阶段角色延续到后一阶段；阶段切换时重新确认当前角色和该阶段输出重点。
- 角色索引缺失、不存在、使用显示名称代替索引、角色职责不匹配或阶段角色前后冲突时，必须在修改任何文件前停止并询问用户。不得自行创造、近似替代或使用默认角色。

## Subagent 执行协议

本 skill 的主会话是协调器，不直接实施方案。通过全局 `subagent` 工具委派一个 `plan-executor` Agent 完成完整执行；主会话负责模型确认、委派、进度接收、中止处理和最终回传。

### 模型确认

在读取实现代码、修改任何文件或启动执行 Agent 前，必须先向 master 询问本次执行使用的精确模型，格式为 `provider/model`，例如 `3r/gpt-5.6-luna`。模型可通过当前 Pi 的 `/model` 或 `pi --list-models` 确认。

- 不得静默使用默认模型、上一次模型或 Agent 文件中的模型。
- master 指定后，向 master 回显将使用的精确模型，并保持该模型贯穿本次方案执行的全部阶段。
- master 说“使用当前模型/默认模型”时，先解析并明确当前的 `provider/model`，再继续。
- 模型不存在、不可用、未认证或 master 未确认时，停止，不读取实现代码、不修改文件。
- 执行中不得自动换模型；需要换模型时先中止本次执行，再由 master 重新确认并启动。

### 委派完整执行

模型确认后，使用全局 user scope 调用 `subagent`：

```json
{
  "agent": "plan-executor",
  "agentScope": "user",
  "model": "<master 已确认的 provider/model>",
  "task": "完整读取并执行方案：<plan path>。遵守 .pi/skills/ai-plan-executor/SKILL.md，完成所有阶段、修改、静态校验、运行验证和最终报告；除非遇到方案规定的阻塞或收到中止信号，不要提前结束。",
  "cwd": "<当前工作目录>"
}
```

- 必须使用 `plan-executor`，不得把完整执行委派给 `scout`、`planner` 或 `worker`。
- 子 Agent 必须完整读取本 skill 和方案，再执行原有的方案读取、角色预检、修改、验证和交付流程。
- `plan-executor` 子 Agent 已经由父会话完成委派；它读取本 skill 时直接执行方案流程，不再重复执行本节的外层模型询问和 subagent 委派，不得递归启动另一个 `plan-executor`。
- 主会话等待 `subagent` 工具结束，不在子 Agent 执行期间自行修改同一方案范围的文件。
- 如果全局 subagent 扩展、`plan-executor` Agent 或模型参数不可用，停止并报告，不静默回退到主会话直接实现。

### 持续执行与当前会话回传

子 Agent 必须持续执行到以下任一终点：

- 方案全部完成并完成可执行的静态/运行验证；
- 方案规定的阻塞条件出现；
- master 主动中止；
- 子进程或模型发生不可恢复错误。

完成后，`subagent` 工具结果必须返回当前主会话。主会话将原样保留执行状态、模型、阶段结果、修改文件、验收、验证和剩余风险，再向 master 汇报；不得要求 master 打开另一个会话或查找临时输出文件。

### 中止处理

在交互式 Pi 中，master 可以使用 `Escape` 中止当前 Agent 回合。Pi 的 abort signal 会传递到 subagent 扩展，扩展终止正在运行的子 Pi 进程，并将状态标记为 `aborted`。

中止后必须：

- 停止新的修改、测试和验证动作；
- 返回已经完成的阶段、当前阶段、已修改文件和未完成步骤；
- 说明工作区可能处于中间状态的风险；
- 不自动重试、不自动换模型、不自动续跑。

只有 master 明确要求继续时，才能以新的执行请求重新开始；重新开始前必须重新确认模型和当前工作区状态。

## 执行流程

### 1. 读取方案

先读取 `Doc/AIPrompt/AI提示词六要素设计指南.md` 和 `Doc/AIPrompt/AIActor/README.md`，再完整读取用户指定的方案 Markdown。提取以下内容：

- `方案元信息`
- `目标`
- `需求范围`
- `非目标`
- `执行约束`
- `阶段角色与职责`
- `实现方案`
- `修改范围`
- `实现步骤`
- `验收标准`
- `代码静态校验`
- `运行验证方式`
- `风险与假设`
- `最终交付要求`

如果方案缺少 `执行约束`、`验收标准`、`代码静态校验` 或 `最终交付要求`，继续执行前先指出缺失项。低风险且可从上下文明确补足时，可以补足执行清单后继续；高风险或跨模块改动必须先向用户确认。`阶段角色与职责` 或必要阶段的 Role 索引缺失时，不适用低风险补足规则，必须停止并询问用户。

### 2. 角色预检

在建立执行清单或编辑任何文件前完成角色预检：

1. 从 `阶段角色与职责` 和 `实现步骤` 提取每个阶段的 Role 索引。
2. 确认两个章节中的阶段与 Role 索引一致，不存在遗漏、冲突或未替换占位符。
3. 确认每个索引与 `Doc/AIPrompt/AIActor/README.md` 的 `角色文档` 链接名称完全一致。
4. 完整读取每个索引对应的角色 Markdown，核对身份、核心职责、判断视角、工作方式和职责边界是否覆盖目标阶段。
5. 确认方案中的本阶段职责没有扩展角色文档，也没有混入 TechStack、Domain、Requirement、Constraints 或 Acceptance。
6. 允许同一 Role 索引覆盖多个符合其职责的阶段，但不得因此扩大角色边界。

以下任一情况出现时，立即停止，不得继续读取实现代码或修改文件：

- 必要阶段没有 Role 索引。
- 索引不在角色目录中，或对应角色文件不存在。
- 方案使用显示名称、临时名称或泛化身份代替 Role 索引。
- `阶段角色与职责` 和 `实现步骤` 的 Role 索引不一致。
- 现有角色文档无法覆盖方案分配的阶段职责。

向用户说明具体阶段、无效或缺失的索引及不匹配原因，并询问用户是修改方案、指定现有 Role 索引，还是先在 `Doc/AIPrompt/AIActor` 新增角色。不得替用户选择“最接近”的角色。

### 3. 建立执行清单

将方案转换成内部执行清单：

| 类别 | 必须提取的内容 |
| --- | --- |
| 允许操作 | 是否允许改代码、改配置、新增测试 |
| 禁止操作 | 非目标、执行约束、禁止触碰的模块 |
| 修改对象 | 文件或模块、修改类型、是否必须、修改目的 |
| 验收对象 | 每条验收标准及判断方式 |
| 验证对象 | 可运行验证、静态校验、人工验证、剩余风险 |
| 阶段角色 | 每个阶段的精确 Role 索引、对应角色文档、职责匹配结论、输出重点、切换条件 |

如果用户只提供方案路径，先读方案并自行建立清单，不要要求用户重复粘贴内容。

### 4. 修改前核对

在编辑文件前完成：

1. 确认角色预检已经通过，并记录每个阶段采用的 Role 索引。
2. 阅读方案指定或推断的现有代码、配置、测试和文档。
3. 对照 `修改范围` 确认实际文件是否存在。
4. 确认关键接口、配置键、类名、方法名、DataSync topic、命令路径或 UI 绑定是否与方案一致。
5. 判断是否存在方案与代码冲突。
6. 如果需要修改方案外文件才能完成目标，先说明原因；只有该文件属于必要依赖且不改变方案边界时才继续。

### 5. 执行修改

按方案的 `实现步骤` 分阶段修改：

- 进入每个阶段前，按方案记录的精确 Role 索引切换角色，并重新读取或回顾对应角色文档的职责与边界。
- 如果执行中发现当前 Role 索引缺失、无法应用或不再适合实际阶段，立即停止并询问用户，不得切换到目录外角色或自行选择替代索引。
- 阶段角色只影响关注点和输出方式，不改变允许操作范围。
- 先做最小必要改动。
- 保持现有架构、命名、异常处理、日志和配置风格。
- 不删除用户已有改动，不回滚无关文件。
- 配置改动必须保留重启、默认值和兼容性说明。
- UI 改动必须考虑绑定、状态、错误提示和现有样式约束。
- 设备、PLC、机器人、IO、调度相关改动必须格外保守，不能伪造硬件验证结论。

### 6. 运行验证

按方案的 `运行验证方式` 执行可运行的验证项。根据实际场景选择：

- 构建受影响项目。
- 运行单元测试或聚焦测试。
- 校验 JSON/XML 配置语法。
- 启动服务或页面做手工验证。
- 对设备/PLC/IO 场景列出模拟器、夹具、dry-run 或人工回归路径。

如果验证失败，先判断是否由本次改动引入。能在范围内修复就修复后重跑；不能修复或与环境有关则记录原因和残余风险。

### 7. 代码静态校验

无论是否运行了测试，都必须执行静态校验。静态校验至少包含：

1. 逐条对照方案元信息、需求范围、非目标、执行约束、实现步骤和验收标准。
2. 标出每项对应的代码位置，至少精确到文件；关键逻辑精确到类、方法或配置键。
3. 沿真实调用链检查数据流、状态流、接口调用、配置读取、错误处理和返回结果。
4. 检查字段名、参数名、配置键、事件名、DataSync topic、返回结构是否前后一致。
5. 检查是否遗漏错误处理、空状态、权限、重复提交、并发、回滚、重启要求或兼容性处理。
6. 检查是否存在条件写反、默认值错误、状态未更新、异常被吞掉、资源未释放等明显逻辑错误。
7. 检查是否引入方案之外的重构、格式化、无关文件修改或行为变化。
8. 列出无法通过静态阅读确认、必须实际运行或联机验证才能确认的风险。
9. 给出最终结论：可以进入下一步 / 需要修改 / 必须运行验证后再判断。

当改动高风险、跨模块、无法运行验证且当前环境支持独立子 agent 或 reviewer 时，建议额外启动独立静态复核。独立复核只读，不参与实现；主执行 agent 仍对最终结论负责。

### 8. 最终交付

最终回复必须按方案的 `最终交付要求` 输出。默认包含：

- 修改文件列表。
- 每个文件的修改说明。
- 逐条验收标准完成情况。
- 执行约束遵守情况。
- 本次 subagent 执行模型、Agent 名称、执行状态和是否中止。
- 阶段角色执行摘要：列出实际经历的阶段、采用的精确 Role 索引、对应角色文档以及是否完整遵守角色边界。
- 已运行的测试或验证命令，以及结果。
- 无法运行验证的原因。
- 代码静态校验报告摘要。
- 剩余风险和需要人工确认的事项。

## 阻塞处理

以下情况应先暂停并向用户说明，不要硬执行：

- 方案缺少关键目标或验收标准，且无法从上下文可靠推断。
- 方案要求与现有代码结构明显冲突，继续执行会扩大范围。
- 方案要求执行高风险硬件、数据库删除、生产配置、批量迁移等操作，但没有验证或回滚要求。
- 必须修改方案明确列为非目标的内容才能完成。
- 需要访问工作区外文件、网络、生产服务或硬件资源，但当前权限不可用。
- 方案缺少必要的 subagent 扩展、`plan-executor` Agent、可用模型或中止能力。
- 方案缺少必要阶段的 Role 索引，或仍包含角色占位符。
- Role 索引不存在于 `Doc/AIPrompt/AIActor/README.md`，或对应文件缺失。
- 方案使用角色显示名称、临时角色或默认角色代替精确索引。
- 角色索引在不同章节中不一致，或角色正文职责无法覆盖目标阶段。

## 最终检查

结束前确认：

- 已完整读取并执行方案，而不是只执行局部片段。
- 已在执行前确认精确的 `provider/model`，并由全局 `plan-executor` subagent 完成执行。
- 已完成角色预检；每个必要阶段都使用 `Doc/AIPrompt/AIActor/README.md` 中的精确 Role 索引。
- 已完整阅读所选角色文档，确认角色适合对应阶段，并按阶段切换且未让角色覆盖执行约束。
- 没有自行创造、近似替代、默认补充或静默更换角色。
- 没有违反非目标和执行约束。
- 修改范围与实际变更一致，差异已解释。
- 验收标准逐条给出结论。
- 静态校验已完成并报告。
- 运行验证已执行可执行部分，未执行部分有原因。
- 剩余风险没有被包装成已完成。
